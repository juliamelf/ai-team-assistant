Шумовые профстандарты похожи формулировками на источники: поиск должен отличать нужные трудовые функции от соседних. Правильный ответ в golden set — только трудовые функции документов `source`. Шум по объёму примерно в 1,8 раза больше источников, поэтому метрики поиска смотрим и отдельно по 06.004 и 06.016.

**Не входят в корпус:** шаблон матрицы компетенций и матрицы компетенций проектов (они в базе, CSV-снимок шаблона — `db/seed/matrix/`), ДИ, профили вакансий, ИПР. Это результаты генерации или структурированные данные, а не источники знаний. Ручные матрицы компетенций и ДИ — эталон для проверки генераторов, в поиск не попадают.


## Контракт данных

### Формат файла

- Один файл на документ: `data/clean/<doc_id>.md`.
- Кодировка UTF-8, переводы строк LF.
- В начале файла — блок метаданных YAML.

### Метаданные

```yaml
---
doc_id: ps-06.004                 # обязательно, совпадает с именем файла
ps_code: "06.004"                 # обязательно для профстандартов
title: Специалист по тестированию в области информационных технологий
doc_type: profstandard            # profstandard | regulation
doc_role: source                  # source | distractor
version: приказ Минтруда России от 2 августа 2021 г. № 531н
valid_to: 1 марта 2028           # срок действия профстандарта, если указан
source_url: https://…
tf_codes: ["06.004:A/01.4", "06.004:A/02.4"]   # все трудовые функции документа
---
```

### Структура текста

Индексация режет текст по заголовкам `###`: один фрагмент — одна трудовая функция. Текст под `##` до первой `###` (должности, требования к образованию) — отдельный фрагмент обобщённой трудовой функции.

```
# Профстандарт 06.004 «…»
Вид профессиональной деятельности: …
Основная цель: …
## 06.004:A — Название обобщённой трудовой функции (уровень квалификации 4)
Возможные наименования должностей, профессий: …
Требования к образованию и обучению: …
### 06.004:A/01.4 — Название трудовой функции
Обобщённая трудовая функция: 06.004:A — … Уровень квалификации 4.
#### Трудовые действия
- …
#### Необходимые умения
- …
#### Необходимые знания
- …
#### Другие характеристики
- …
```

- Код трудовой функции всегда с номером профстандарта: `06.004:A/01.4`. Коды в разных профстандартах повторяются.
- Каждый пункт таблицы профстандарта — отдельная строка списка. Таблиц в тексте нет.
- Пустых блоков нет: если в профстандарте раздел пуст, заголовок не пишется.

### Что удаляется при очистке

- Колонтитулы, номера страниц, водяные знаки («Документ предоставлен…»), переносы слов.
- Раздел I «Общие сведения» (коды ОКЗ и ОКВЭД при необходимости — в метаданные).
- Раздел II «Функциональная карта» — дублирует раздел III.
- Раздел IV «Сведения об организациях-разработчиках».

### Персональные данные

В корпусе нет персональных данных. Профстандарты — открытые нормативные документы.

### Обновление

Новая редакция документа: новый файл в `raw/`, новый `sha256_raw` и `version` в манифесте, правка `clean/`, переиндексация. Старая редакция из `clean/` удаляется.

## Как собирается корпус

```
python src/corpus/convert_ps.py data/raw data/clean data/manifest.csv
python src/corpus/check_corpus.py data/clean data/manifest.csv db/seed/matrix/competencies.csv data/raw
```

`convert_ps.py` разбирает docx из КонсультантПлюс и пишет `.md` и манифест. `check_corpus.py` выполняет проверки ниже; код выхода 1 — есть ошибки.

## Проверки перед индексацией

1. У всех файлов есть метаданные, у каждой трудовой функции — заголовок `###` с полным кодом.
2. `tf_count` совпадает с оригиналом.
3. Каждая компетенция из `db/seed/matrix/competencies.csv` находит свою трудовую функцию в документе-источнике.
4. Нет мусора: «КонсультантПлюс», «consultant.ru», «Гарант», «Страница», «стр.», «ОКЗ», «None». (Слово «Консультант» само по себе встречается в названиях должностей и мусором не считается.)
6. Число трудовых функций в `.md` совпадает с числом кодов в оригинале docx.
5. Нет пустых блоков.
