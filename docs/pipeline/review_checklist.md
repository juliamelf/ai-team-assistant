# Чек-лист ревью кода

Задача: … · Спецификация: версия … · Круг ревью: 1 / 2 / 3 · Дата: …

Ответы: «да», «нет», «н/п» (неприменимо). На каждое «нет» — замечание в таблице внизу.

## 1. Соответствие спецификации

- [ ] Реализован каждый шаг раздела «Поведение»
- [ ] Входы и выходы совпадают со спецификацией по формату и именам
- [ ] Нет функциональности сверх спецификации
- [ ] Каждый критерий приёмки достижим этим кодом

## 2. Правильность

- [ ] Крайние случаи из спецификации обработаны (пустой вход, повреждённый файл, дубли)
- [ ] Повторный запуск ведёт себя так, как описано в ограничениях
- [ ] Нет ошибок на границах: пустой список, последний элемент, нулевая длина
- [ ] Типы и единицы согласованы (символы и токены, секунды и миллисекунды)

## 3. Секреты и данные

- [ ] Ключи, пароли и токены читаются из окружения, в коде их нет
- [ ] Секреты и персональные данные не попадают в логи и сообщения об ошибках
- [ ] `.env` и файлы с данными перечислены в `.gitignore`
- [ ] SQL-запросы с параметрами, без склейки строк

## 4. Ошибки и внешние сервисы

- [ ] У сетевых вызовов есть таймаут
- [ ] Повторы при временных ошибках ограничены по числу и с паузой
- [ ] Ошибка не проглатывается молча: либо обработана, либо понятно сообщена
- [ ] При сбое посреди работы данные не остаются в полузаписанном состоянии
- [ ] Соединения и файлы закрываются (`with`)

## 5. Тестируемость и читаемость

- [ ] Логика вынесена в функции, которые можно вызвать из теста без сети и базы
- [ ] Настройки (размер фрагмента, модель, пути) вынесены в параметры или конфигурацию
- [ ] Имена функций и переменных говорят, что они делают
- [ ] Нет мёртвого и закомментированного кода
- [ ] Есть логирование ключевых шагов: сколько обработано, сколько пропущено

## 6. Зависимости и запуск

- [ ] Используются только библиотеки из спецификации, версии закреплены в `requirements.txt`
- [ ] Код запускается командой из спецификации на чистом окружении
- [ ] Все импортируемые библиотеки и вызываемые методы реально существуют (модель не выдумала)
