# Шаблон тестов

Тесты пишутся по критериям приёмки из спецификации, до чтения кода. Один критерий — минимум один тест.

## 1. Покрытие критериев

| Критерий | Тест | Вид | Нужны сеть или база |
| --- | --- | --- | --- |
| AC-1 | `test_ac1_…` | позитивный | нет |
| AC-2 | `test_ac2_…` | негативный | нет |
| AC-3 | `test_ac3_…` | интеграционный | да |

Критерий без теста — пометить «проверяется вручную» и описать, как.

## 2. Правила

- Имя теста: `test_ac<номер>_<что проверяем>`.
- Структура: подготовка → действие → проверка.
- Тесты без сети и базы запускаются всегда. Внешние сервисы подменяются заглушками.
- Тесты, которым нужны настоящий API или база, помечаются `@pytest.mark.integration` и запускаются отдельно.
- Тестовые данные — маленькие файлы в `tests/data/`, без настоящих персональных данных.
- На каждый негативный случай из раздела «Ошибки и крайние случаи» — отдельный тест.

## 3. Каркас

```python
# tests/test_<модуль>.py
import pytest

from src.<модуль> import <функция>


def test_ac1_<что_проверяем>():
    # подготовка
    data = ...
    # действие
    result = <функция>(data)
    # проверка
    assert result == ...


def test_ac2_<ошибка_на_пустом_входе>():
    with pytest.raises(ValueError):
        <функция>("")


@pytest.mark.integration
def test_ac3_<запись_в_базу>():
    ...
```

## 4. Запуск

```
pytest -m "not integration"     # быстрые тесты, без сети и базы
pytest -m integration           # с настоящими сервисами
```

Метку нужно один раз объявить в `pytest.ini`:

```
[pytest]
markers =
    integration: тесты с настоящими внешними сервисами
```

## 5. Что записать после первого запуска

Сразу, до любых правок кода: сколько тестов всего, сколько упало, какие. Эти числа идут в `pipeline_log.csv` (`tests_total`, `tests_failed_first_run`, `passed_first_run`).
