## 1. Цель

Скрипт режет очищенные профстандарты из `data/clean/*.md` на фрагменты по трудовым функциям, получает для каждого фрагмента эмбеддинг моделью Giga-Embeddings-instruct-3B (Evolution Foundation Models, cloud.ru) и записывает фрагменты с метаданными и векторами в PostgreSQL (pgvector). По этой таблице потом работают гибридный поиск, генератор матрицы компетенций проекта и оценка поиска по golden set.

## 2. Что входит и что не входит

- Входит:
  - разбор файлов `data/clean/*.md` по контракту из `data/README.md` (метаданные YAML, заголовки `#`, `##`, `###`);
  - нарезка на фрагменты: вводная часть документа, обобщённая трудовая функция, трудовая функция;
  - эмбеддинги моделью `ai-sage/Giga-Embeddings-instruct-3B` через OpenAI-совместимый API cloud.ru пакетами, с повторами при ошибках;
  - миграция `db/migrations/08_rag_chunks.sql`: схема `rag`, таблица `rag.chunks`;
  - запись в базу с повторным запуском без дублей: неизменённые фрагменты пропускаются без вызова API;
  - режим `--dry-run`, в котором нет обращений к API и базе, есть только разбор и отчёт;
  - отчёт о прогоне в консоль и код выхода.
- Не входит:
  - разбор docx/pdf (уже сделано в `src/corpus/convert_ps.py`);
  - проверки корпуса из `src/corpus/check_corpus.py` (их запускает человек до индексации);
  - полнотекстовый индекс (tsvector, pg_trgm), функция поиска, rerank — это задача «Гибридный поиск»;
  - индекс ANN (HNSW, ivfflat): при ~535 строках точный поиск достаточен, решение принимается в задаче «Гибридный поиск»;
  - эмбеддинги запросов пользователя (для них модель требует инструкцию перед текстом запроса; документы индексируются без инструкции);
  - индексация чего-либо кроме `data/clean/*.md`.

| Выход | Куда | Формат | Пример |
| --- | --- | --- | --- |

### Таблица `rag.chunks` (миграция `db/migrations/08_rag_chunks.sql`)

```sql
CREATE EXTENSION IF NOT EXISTS vector;
CREATE SCHEMA IF NOT EXISTS rag;

CREATE TABLE IF NOT EXISTS rag.chunks (
    chunk_id            text PRIMARY KEY,           -- 'ps-06.004#06.004:A/01.4'
    doc_id              text NOT NULL,              -- 'ps-06.004'
    ps_code             text NOT NULL,              -- '06.004'
    doc_type            text NOT NULL,              -- 'profstandard'
    doc_role            text NOT NULL CHECK (doc_role IN ('source', 'distractor')),
    doc_version         text NOT NULL,              -- 'приказ Минтруда России от …'
    chunk_type          text NOT NULL CHECK (chunk_type IN ('doc', 'otf', 'tf')),
    otf_code            text,                       -- '06.004:A' (для otf и tf)
    tf_code             text,                       -- '06.004:A/01.4' (только для tf)
    qualification_level smallint,                   -- 4 (для otf и tf)
    heading             text NOT NULL,              -- заголовок фрагмента без решёток
    text                text NOT NULL,              -- текст, который ушёл в эмбеддинг
    content_hash        text NOT NULL,              -- sha256 от модели и текста
    embedding_model     text NOT NULL,              -- 'ai-sage/Giga-Embeddings-instruct-3B'
    embedding           vector(2048) NOT NULL,
    indexed_at          timestamptz NOT NULL DEFAULT now()
);

CREATE INDEX IF NOT EXISTS chunks_doc_id_idx ON rag.chunks (doc_id);
CREATE INDEX IF NOT EXISTS chunks_tf_code_idx ON rag.chunks (tf_code);

INSERT INTO app.schema_migrations (version, note)
VALUES ('08', 'rag.chunks — фрагменты корпуса профстандартов с эмбеддингами')
ON CONFLICT (version) DO NOTHING;
```

Миграция идемпотентна, как и остальные в `db/migrations/`.

## 5. Поведение

1. Прочитать аргументы: папка корпуса, `--doc`, `--dry-run`. Если не `--dry-run`, проверить переменные окружения из раздела 3.
2. Для каждого файла `*.md` (в алфавитном порядке, или только `--doc`) разобрать блок метаданных и проверить обязательные поля.
3. Разрезать текст после блока метаданных на фрагменты по заголовкам:
   - **doc**: текст от заголовка `# ` до первого `## ` (название профстандарта, вид деятельности, основная цель). Один на документ.
   - **otf**: текст от заголовка `## ` до первого `### ` внутри него (должности, требования к образованию). Один на каждую обобщённую трудовую функцию.
   - **tf**: текст от заголовка `### ` до следующего `### ` или `## `, включая все подзаголовки `####`. Один на каждую трудовую функцию.
4. Заполнить метаданные фрагмента:
   - `chunk_id` = `<doc_id>#doc`, `<doc_id>#<код ОТФ>`, `<doc_id>#<код ТФ>`;
   - `otf_code` — код из заголовка `##` (`06.004:A`); для tf — код ОТФ, в которую входит ТФ;
   - `tf_code` — код из заголовка `###` (`06.004:A/01.4`);
   - `qualification_level`: для tf — цифра после последней точки кода (`A/01.4` → 4); для otf — число из «(уровень квалификации N)» в заголовке;
   - `heading` — текст заголовка без `#` и пробелов по краям.
5. Проверить документ: коды ТФ из заголовков `###` в том же порядке совпадают с `tf_codes` из метаданных, повторов нет, ни один фрагмент не длиннее `MAX_CHUNK_CHARS = 12000` символов. При нарушении документ пропускается целиком (см. раздел 7).
6. Собрать текст для эмбеддинга:
   - doc: текст фрагмента как есть, без пустых строк в конце;
   - otf и tf: первая строка `Профстандарт <ps_code> «<title>»`, пустая строка, затем текст фрагмента вместе с его заголовком, без пустых строк в конце.
7. Посчитать `content_hash` = sha256 (hex) от строки `<embedding_model>\n<текст для эмбеддинга>`.
8. Если `--dry-run`, напечатать по документу число фрагментов по типам и перейти к следующему. К API и базе не обращаться.
9. Получить из хранилища хэши уже записанных фрагментов этого `doc_id`. Разделить фрагменты на новые (нет `chunk_id`), изменённые (хэш другой) и без изменений (хэш совпадает). Фрагменты из базы, которых больше нет в документе, пометить к удалению.
10. Эмбеддинги получить только для новых и изменённых фрагментов: пакетами по `BATCH_SIZE = 16` текстов, моделью `ai-sage/Giga-Embeddings-instruct-3B` (метод `embeddings.create` клиента `openai`), с таймаутом запроса 60 с. Проверить, что каждый вектор длиной 2048.
11. Записать документ одной транзакцией: вставить новые, обновить изменённые (все поля, `indexed_at = now()`), удалить лишние. Если на шагах 10–11 произошла ошибка, по этому документу в базе ничего не меняется.
12. Напечатать строку отчёта по документу. После всех документов напечатать итог: документов всего, успешно, с ошибками; фрагментов всего, новых, изменено, без изменений, удалено; список ошибок.
13. Завершиться с кодом выхода из раздела 4.

## 6. Ограничения

- Язык и версия: Python 3.14.
- Разрешённые библиотеки: стандартная библиотека, `openai`, `psycopg` (3), `pgvector`, `python-dotenv`. YAML разбирать без новых зависимостей: блок метаданных простой, формат `ключ: значение`, `tf_codes` в виде списка в квадратных скобках со строками в двойных кавычках (как в `check_corpus.py`). Новые библиотеки только по согласованию.
- Секреты: только из `.env` через `python-dotenv`; в коде, отчёте, логах и текстах исключений их нет. Проверку SSL не отключать.
- Объём: 9 документов, около 940 тыс. символов, 535 фрагментов. Самый длинный фрагмент около 5 тыс. символов, это укладывается в окно модели (8К токенов). Ожидаемый расход около 0,3 млн токенов, по цене 32,22 ₽ за 1 млн — около 10 ₽ за полную индексацию.
- Лимиты API: запросы идут последовательно, без параллельности.
- Повторы: при ошибке API (сеть, таймаут, 429, 5xx) до 3 попыток с паузами 2, 4, 8 с. Ошибки 401 и 403 не повторяются.
- Повторный запуск: дубли недопустимы. Неизменённые фрагменты не отправляются в API и не перезаписываются. Повторный запуск без изменений корпуса делает 0 вызовов API и 0 изменений в базе.
- SQL только с параметрами, без склейки строк.

## 7. Ошибки и крайние случаи

| Ситуация | Ожидаемое поведение |
| --- | --- |
| Нет блока метаданных или не хватает обязательного поля | Документ пропускается, ошибка «<файл>: нет метаданных / пустое поле <поле>» в отчёте, остальные документы обрабатываются, код выхода 1 |
| `doc_id` в метаданных не совпадает с именем файла | Документ пропускается, ошибка в отчёте |
| Коды `###` не совпадают с `tf_codes` или есть повторы | Документ пропускается, ошибка в отчёте |
| Фрагмент длиннее 12 000 символов | Документ пропускается, ошибка с `chunk_id` и длиной |
| Пустой файл или нет ни одного заголовка `###` | Документ пропускается, ошибка в отчёте |
| `###` встречается до первого `##` | Документ пропускается, ошибка в отчёте |
| API недоступен, таймаут, 429, 5xx | До 3 повторов (раздел 6); если не помогло — документ пропускается, в базе по нему ничего не меняется, ошибка в отчёте, переход к следующему документу |
| API ответил 401 или 403 | Без повторов. Работа останавливается: дальше будет та же ошибка. Код выхода 1, в отчёте — какие документы не обработаны |
| Вектор не длины 2048 или число векторов не совпадает с числом текстов | Документ пропускается, в базе по нему ничего не меняется, ошибка в отчёте |
| База недоступна при старте | Ошибка до начала работы, код выхода 2 |
| Ошибка базы при записи документа | Откат транзакции документа, ошибка в отчёте, переход к следующему |
| Таблицы `rag.chunks` нет | Ошибка до начала работы с подсказкой применить `08_rag_chunks.sql`, код выхода 2 |
| Документ удалён из `data/clean/` | Скрипт не трогает его фрагменты в базе. Удаление целого документа — вручную, в отчёт не входит |

## 8. Критерии приёмки

| № | Критерий | Как проверяется |
| --- | --- | --- |
| AC-1 | Дано `ps-06.004.md` — когда документ разрезан — тогда получено 1 фрагмент doc, 4 фрагмента otf и 20 фрагментов tf; коды tf совпадают с `tf_codes` из метаданных и идут в том же порядке | автотест на реальном файле `data/clean/ps-06.004.md` |
| AC-2 | Дано небольшой выдуманный документ по контракту — когда он разрезан — тогда у каждого фрагмента верные `chunk_id`, `chunk_type`, `otf_code`, `tf_code`, `qualification_level`, `heading`, `doc_id`, `ps_code`, `doc_role`, `doc_type`, `doc_version` | автотест |
| AC-3 | Дано фрагмент tf или otf — тогда текст для эмбеддинга начинается со строки `Профстандарт <ps_code> «<title>»` и содержит заголовок фрагмента и все подразделы `####`; текст doc начинается с `# Профстандарт` | автотест |
| AC-4 | Дано одинаковый текст и модель — тогда `content_hash` одинаковый; другой текст или другая модель — другой хэш | автотест |
| AC-5 | Дано весь корпус `data/clean` — когда запуск с `--dry-run` — тогда в отчёте 9 документов, 535 фрагментов (9 doc, 35 otf, 491 tf), ошибок 0, и нет ни одного вызова embed и хранилища | автотест с заглушками embed и хранилища, которые падают при вызове |
| AC-6 | Дано пустое хранилище — когда индексируется документ — тогда все фрагменты записаны с векторами, embed вызван пакетами не больше 16 текстов | автотест с заглушками |
| AC-7 | Дано документ уже проиндексирован — когда повторный запуск без изменений — тогда 0 вызовов embed, 0 записей и удалений, в отчёте все фрагменты «без изменений» | автотест с заглушками |
| AC-8 | Дано в одной ТФ изменился текст — когда повторный запуск — тогда embed вызван ровно для одного текста, обновлён один фрагмент | автотест с заглушками |
| AC-9 | Дано из документа убрана ТФ (и из `tf_codes`) — когда повторный запуск — тогда её фрагмент удалён из хранилища | автотест с заглушками |
| AC-10 | Дано в корпусе один документ без метаданных и один верный — когда запуск — тогда верный проиндексирован, у неверного ошибка в отчёте, код выхода 1 | автотест |
| AC-11 | Дано коды `###` не совпадают с `tf_codes` / фрагмент длиннее 12 000 символов / `###` до `##` — тогда документ пропущен с ошибкой, хранилище по нему не вызывается | автотесты, по одному на случай |
| AC-12 | Дано embed падает с временной ошибкой два раза, на третий успешно — тогда документ проиндексирован; паузы 2 и 4 с (функция sleep подменяется) | автотест |
| AC-13 | Дано embed падает все 3 попытки — тогда по документу в хранилище ничего не записано и не удалено, ошибка в отчёте, следующий документ обработан | автотест |
| AC-14 | Дано embed вернул вектор длины 1024 — тогда документ пропущен, в хранилище ничего не записано | автотест |
| AC-15 | Дано ошибка 401/403 от embed — тогда повторов нет, обработка остальных документов остановлена, код выхода 1 | автотест |
| AC-16 | Дано в окружении задан `CLOUDRU_API_KEY` — когда любой запуск, включая ошибки — тогда значение ключа не появляется в stdout и stderr | автотест с выдуманным ключом и перехватом вывода |
| AC-17 | Дано миграция 08 применена дважды — тогда ошибок нет, таблица одна | команда `psql -f db/migrations/08_rag_chunks.sql` два раза, вручную |
| AC-18 | Дано реальные API cloud.ru и база — когда полный запуск — тогда `SELECT count(*) FROM rag.chunks` = 535, `vector_dims(embedding)` = 2048 у всех строк, повторный запуск даёт 0 вызовов API | `@pytest.mark.integration` или вручную по SQL ниже |

Проверка AC-18 вручную:

```sql
SELECT chunk_type, count(*) FROM rag.chunks GROUP BY chunk_type;          -- doc 9, otf 35, tf 491
SELECT count(*) FROM rag.chunks WHERE vector_dims(embedding) <> 2048;     -- 0
SELECT doc_role, count(DISTINCT doc_id) FROM rag.chunks GROUP BY doc_role; -- source 2, distractor 7
```

### Интерфейс для тестов

Тесты пишет другая модель, не видя кода, поэтому имена и сигнатуры фиксируются здесь и разработчик их не меняет.

| Модуль | Функция или класс | Аргументы и типы | Возвращает | Исключения |
| --- | --- | --- | --- | --- |
| `src.rag.chunking` | `Chunk` | `@dataclass(frozen=True)`, поля: `chunk_id: str`, `doc_id: str`, `ps_code: str`, `doc_type: str`, `doc_role: str`, `doc_version: str`, `chunk_type: str` (`"doc"`/`"otf"`/`"tf"`), `otf_code: str \| None`, `tf_code: str \| None`, `qualification_level: int \| None`, `heading: str`, `text: str`, `content_hash: str` | — | — |
| `src.rag.chunking` | `CorpusFormatError` | наследник `ValueError` | — | — |
